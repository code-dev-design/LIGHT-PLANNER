# POC-01 — Vector PDF Core Validation

## الهدف
إثبات أن ملفات PDF الحقيقية الخاصة بالعميل يمكن تصنيفها بصورة صحيحة، واستخراج العناصر المتجهية منها، ثم استخدامها كأساس للتحرير والقياس داخل المحرر قبل توسيع الدعم إلى DXF/DWG.

## ما نثبته في هذا الاختبار
1. التمييز بين Vector PDF وRaster/Scanned PDF.
2. استخراج الخطوط والمنحنيات والمستطيلات/الأشكال والنصوص من الصفحات المتجهية.
3. قياس كثافة العناصر لكل صفحة لتحديد حالات الضغط والأداء.
4. اكتشاف المقياس المكتوب على الصفحة عندما يكون موجودًا.
5. اختيار ملفات ممثلة للاختبار اليدوي داخل المحرر.
6. بعد ذلك: التحقق من Select / Move / Delete / Add Line / Measure / Calibrate على نفس الملفات.

## ملاحظة مهمة
نجاح PDF لا يعني تلقائيًا نجاح DXF أو DWG. المطلوب هو تثبيت النموذج الداخلي للمحرر وآلية العمل؛ ثم ستُبنى لكل صيغة طبقة Import/Conversion خاصة بها لتغذية نفس النموذج الداخلي.

## نتائج أولية من عينات العميل المتوفرة
- توجد عينات PDF متجهية كثيفة جدًا ومناسبة لاختبار الأداء.
- توجد ملفات مختلطة تحتوي عناصر متجهية وصورًا معًا.
- توجد ملفات/صفحات Raster لا تحتوي Geometry متجهية قابلة للتحرير، ويجب أن تعامل كخلفية فقط.
- بعض الملفات تتضمن Scale نصيًا واضحًا مثل 1:50 و1:100 و1:200، لكن الاعتماد على النص وحده غير كافٍ ويجب التحقق بقياس مرجعي معروف.

## معايير النجاح للمرحلة الأولى
- يحدد النظام نوع الصفحة بوضوح: Vector / Mixed / Raster.
- لا يدعي أن Raster PDF قابل للتحرير كـCAD.
- تعرض الصفحة المتجهية بدون فقد واضح في الشكل العام.
- يمكن تحديد عنصر مستخرج واحد على الأقل وتحريكه وحذفه وإضافة خط جديد.
- يمكن معايرة/قياس بعد معروف داخل المخطط والتحقق من النتيجة.
- لا ينهار المحرر على ملف ممثل عالي الكثافة؛ وإذا تجاوز الملف قدرة النسخة الحالية تظهر حالة واضحة بدل الفشل الصامت.

## الخطوة التالية بعد التصنيف
تشغيل ملفات مختارة داخل الديمو على Branch `phase-04-vector-pdf-poc` وإجراء اختبار التحرير والقياس المرئي، ثم توثيق Pass / Fail / Limit لكل ملف.
